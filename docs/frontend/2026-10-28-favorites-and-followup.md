# 收藏与选定跟进拆分

## 用户流程

1. 聊天普通房源卡、通勤卡、比较卡和推荐列表均有“收藏房源”与“选定并跟进”。收藏无需先确认需求，可以保留多套；收藏后按钮变成“取消收藏”。
2. 聊天和推荐页顶部的“我的收藏（N）”打开同一个案例的收藏抽屉，支持地址/区域筛选、详情、移除，以及勾选 2–4 套并排比较周租、卧室、浴室、车位及到校通勤。
3. “选定并跟进”会弹出明确确认框；替换已有跟进房源时提示替换。选定后显示“当前跟进房源”，共享原有看房询问、用户记录、租约草稿和合同复核入口。
4. 取消收藏不清空当前跟进房源或记录；选定或替换不清空收藏。原有选定房源仍保留在跟进入口，不自动改成收藏。每次新选定沿用现有独立跟进上下文规则，旧记录和合同基线保留。

## 数据与接口

- `favorites` SQLite 对象按案例保存多套房源快照及收藏时间，独立于 `case.selection` 和确认需求。
- `GET /api/v1/cases/{case_id}/favorites` 返回 `{case_id, items:[{listing,saved_at,in_catalog}]}`。读取时补充当前房源资料；广告移出房源库后保留快照并禁止选定，仍可移除收藏。
- `POST .../favorites` 接收 `{request_id, listing_id, saved:boolean}`，去重且幂等；重放旧请求不会撤销后续收藏动作，响应返回当前收藏列表。回执只存操作结果，避免为每次收藏重复保存整份收藏列表。
- `POST .../followup-selection` 接收 `{request_id,expected_profile_fingerprint,listing_id,confirmed:true}`。同一事务内核对当前确认需求、生成真实筛选报告并选择对应房源；预算、区域、户型或通勤不符合时拒绝并回滚。收藏本身没有这些门槛。
- 聊天卡片原有选定接口继续保留已展示房源及需求同步检查，更新对用户的文案。现有 selection、followup、合同结构无迁移。
- 前端 FavoritesProvider 按案例挂载，在聊天和推荐页切换时共享收藏状态；切换案例时隔离状态。
