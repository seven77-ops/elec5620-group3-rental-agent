# Real data workbench

Implemented locally on `codex/local-ai-integration` on 21 October 2026. This is a real-data collection and historical-reference feature; formal recommendation and contract processing retain their existing synthetic-only input rules. No provider subscription, signup, external model call or live data-provider request was performed in this change.

## Start and use

From the parent project, double-click `start-real-data.command`. It starts the local UI at http://127.0.0.1:5191 and API at http://127.0.0.1:8011 using the separate `.runtime/real-data-local` store. Alternatively, from this repository:

```sh
RENTAL_RUNTIME_DIR="$PWD/.runtime/real-data-local" .venv/bin/python scripts/dev.py --web-port 5191 --api-port 8011
```

Create a local case and choose **真实数据**. No preference confirmation is required to browse this research page.

1. **租金参考:** select postcode, one/two-bedroom flat and rental price scope. Optionally enter an advertisement's base rent, excluding separate bills and fees. The UI shows monthly calculated and quarterly official medians, quartiles, sample counts, periods and source links. Room/per-person prices are explicitly not compared with whole-property cohorts.
2. **真实房源:** enter source link, address/locality, postcode, weekly rent, scope and actual observation time. Unknown bills, bedrooms and coordinates may remain blank. Coordinates must be supplied as a pair. At most 30 immutable observation records per case are stored in SQLite; requests are idempotent, records survive refresh, and JSON export includes provenance. An observation within 24 hours does not certify current availability, correctness or data-use permission.
3. **通勤查询:** enter origin coordinates, actual campus-building/entrance coordinates and a future arrival date/time. Browser-local input is converted to an offset-aware instant, then to Sydney time for TfNSW. Arrival is bounded to the next 30 days; provider timetable availability may be shorter. Total elapsed planned duration includes transfer waits. Unknown timing or walking classification remains unknown. Source/map links open only when deliberately followed; there is no map SDK, automatic geocoding or background polling.

Provider advertisements and manual records are not passed to an LLM, the ranking engine, SelectedListingEvidence or Agent3. End-to-end real recommendations require further evidence adaptation for lease windows, availability, pricing scope, bills, permission and contract inputs. Domain's Rental AVM is researched but not called or integrated here.

## Server-only configuration

The existing `scripts/dev.py` loads these additional allowlisted variables from the local ignored `.env`. Existing environment values take precedence; no shell expansion is performed.

```dotenv
TFNSW_API_KEY=
DOMAIN_API_KEY=
DOMAIN_USE_APPROVED=0
```

Register a TfNSW application to obtain the first key. For Domain, obtain an appropriate package and confirm the intended application/data use, then set `DOMAIN_USE_APPROVED=1`. The setting records the developer's configuration; it is not an automated licence verification. Restart the API after editing `.env`. Do not use a `VITE_*` variable for secrets.

The product checks keys/approval locally and displays readiness; it cannot establish provider-side entitlement until a real query succeeds. Every external query requires explicit opt-in. No credentials currently exist for these providers on this machine; authenticated compatibility, current availability and real route output remain unverified.

Provider requests use fixed official hosts, no redirects, a 12-second total deadline, a 1 MB streamed response cap, strict JSON and redacted error messages. There are no automatic retries. The existing transport event loop is shared with AI HTTP transport, but the real-data feature does not invoke a model.

## Snapshot and provenance

The checked-in runtime artifact is `agent2/data/market/nsw-usyd-2026.json`. It contains 16 cohorts: four postcodes (2008/2037/2042/2050), two bedroom counts and two periods. Coverage is limited to flats/units. It loads without network access or a dependency on the parent directory. Original research workbooks and their manifest remain at the parent project's `data/research/2026-10-21/`.

- [NSW Fair Trading rental bond data](https://www.nsw.gov.au/housing-and-construction/rental-forms-surveys-and-data/rental-bond-data): September 2026 registration records, independently grouped by postcode, dwelling type F and bedroom count. Positive numeric rents only; no outlier trimming. Quartiles use inclusive linear interpolation. These are calculated research statistics, not the official Rent Check results.
- [NSW DCJ rent tables](https://dcj.nsw.gov.au/about-us/families-and-communities-statistics/housing-rent-and-sales/rent-and-sales-report.html): official April–June 2026 postcode/flat/bedroom statistics, preserved as published.
- Source download URLs, SHA256 values and official worksheet ranges accompany the artifact. Postcodes can contain multiple suburbs. No exact-address, size, furnishing or clean shared-room equivalence is established. Cross-period figures do not alone demonstrate a price trend.

Rebuild from the research source directory with the bundled Python runtime containing openpyxl:

```sh
python tools/build_market_snapshot.py --research-dir ../../data/research/2026-10-21 --output agent2/data/market/nsw-usyd-2026.json
```

The builder verifies original workbook hashes and independently computes the snapshot; openpyxl is not a runtime server dependency. An independent reviewer rebuilt it and obtained identical content.

## API

| Method/path after `/api/v1` | Behavior |
|---|---|
| `GET /real-data/config` | Coverage and non-secret provider readiness |
| `GET /real-data/market` | `postcode`, integer `bedrooms`, `rent_scope`, optional numeric `weekly_rent` |
| `POST /cases/{case_id}/real-listings` | `request_id` plus a strictly validated `listing` |
| `GET /cases/{case_id}/real-listings` | Read saved manual records, recomputing age without changing observation times |
| `GET /cases/{case_id}/real-listings/export` | Download saved research observations |
| `POST /real-data/domain-search` | `postcode`, `maximum_weekly_rent`, `allow_external: true`; first 20 rental advertisements only |
| `POST /real-data/trips` | `origin` and `destination` latitude/longitude objects, offset-aware `arrival_at`, `allow_external: true` |

Validation refuses unknown fields, bool-as-number, huge/nonfinite values, invalid source links, future observation times, half-supplied coordinate pairs and unsupported scopes. Arbitrary URLs are never fetched. Provider responses with invalid structure fail without revealing response bodies or credentials. HTTP transactions are not held open during provider requests.
