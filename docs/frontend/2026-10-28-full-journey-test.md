# 全流程测试用例：从找房到退租押金

用例编号：E2E-001。优先级：P0。目标：同一个新案例完整经过 Agent1 需求、Agent2 房源推荐、Agent3 合同、Agent4 租后及退租收尾，验证各阶段保存的数据能正确衔接。

自动化文件：`frontend/e2e/full-rental-journey.spec.ts`。

聊天连续修改的回归用例：`frontend/e2e/commute-short-updates.spec.ts`。复现先要求“步行10分钟”得到零结果，再直接输入“公共交通20分钟”；检查条件栏、推荐理由、完整匹配数量和刷新恢复均更新，预算及户型保留。脚本默认同时运行完整主流程、聊天通勤回归和 `single-selection.spec.ts` 的选房交互回归。

## 一键运行

在当前工作区根目录执行：

```bash
.venv/bin/python scripts/test_full_journey.py
```

前提：项目 `.venv` 已安装后端依赖，`frontend/node_modules` 已安装前端及 Playwright 依赖。本机优先使用已安装的 Google Chrome；也可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定浏览器路径，或使用 Playwright 已安装的 Chromium。

脚本自动选择两个空闲端口，启动临时 API 和前端，创建独立数据库，执行测试，最后停止自己启动的进程。不会连接正在使用的 5191/8011 服务，也不会修改 `.runtime/real-data-local`。直接执行普通 Playwright 测试命令时，此用例默认跳过，避免意外向日常环境写入测试案例。

终端会输出本次运行目录，其中包含：

- `report/index.html`：中文分步骤执行报告。
- `artifacts/`：关键截图、下载的 PDF、最终案例数据；失败时附截图及 Playwright trace。
- `servers.log`：临时服务日志。
- `database/`：本次独立数据库，保留以方便定位失败，复测会另建目录。

AI 意图识别和报修润色使用固定测试替身，不调用外部模型。房源目录、筛选、真实匹配计数、收藏、合同复核、PDF 生成、保存与恢复均使用项目实际实现。本用例验证完整业务主路径；模型回答质量、真实交通接口可用性、真实签约、邮件发送、商家预约和银行退款不属于这条自动化用例的验证范围。

## 测试数据

使用现有真实房源目录，每次通过首页新建案例，不写死房源 ID 或数量。

- 首条需求：`想找悉大步行20分钟以内的整租，每周1200澳元，至少1卧1卫，1人入住，不限区域。`
- 零结果预算：从满足步行及户型条件的实际最低周租减 25；点击“预算增加 50”后，应有真实匹配结果。
- 后续将交通改为公共交通，单程最多 30 分钟，预算恢复 1200。
- 跟进租金：选定房源广告周租加 20，用来验证跟进事实与广告值的区分。
- 上传复核的测试合同租金：再加 10，故意制造差异。此差异只能提示核对，不能偷偷覆盖原跟进记录或已保存草稿。
- 测试姓名：`E2E Example Owner`、`E2E Example Tenant`、`E2E Agency`。
- 中介联系方式：`agent@example.com; Phone: 0400000001`，均为测试资料。
- 起租日：运行年份下一年的 1 月 1 日；结束日：再下一年的 1 月 1 日，避免固定日期随时间失效。
- 搬运报价 250 AUD；押金测试编号 `E2E-BOND-001`。

## 验收标准

自动化用例的全部步骤通过，关键截图和 PDF 能打开，最终数据中选房、合同、联系人、报修及退租地址一致；无页面未捕获错误。失败时报告必须准确定位到步骤，不能以“页面能打开”代替全链路成功。

这是一条完整主流程用例，不是穷举所有异常。断网、并发版本冲突、历史版本、取消操作、押金争议和操作员门禁等分支，继续由现有模块测试分别覆盖。
