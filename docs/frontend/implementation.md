# 统一前端运行说明

此应用基于 [v0.1 前端方案](2026-10-17-frontend-plan.md) 和 [实施交接文档](2026-10-17-frontend-handoff.md)，将租客页面连接到原 Agent 2、3、4 Python 实现。Agent 1 使用明确标注的模拟偏好表单。默认仅处理合成演示输入，外部模型和对外发送关闭。

## 安装与启动

在包含 `agent2/agent3/agent4/frontend/server` 的本仓库根目录执行。Python 3.11+；本次安装与构建使用 Python 3.13.2、Node 22.23.1、npm 10.9.8。

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r server/requirements-lock.txt
(cd frontend && npm ci)
.venv/bin/python scripts/dev.py
```

打开 <http://127.0.0.1:5173>。API 文档为 <http://127.0.0.1:8000/docs>。两个端口均只监听 `127.0.0.1`；Ctrl+C 停止两个服务。不要同时运行多份占用相同端口的进程。

启动脚本在未设置 `RENTAL_OPERATOR_KEY` 时，将随机本地操作员密钥写入忽略目录 `.runtime/operator-key.txt`，并只打印文件位置。需要演示人工决定时，在本机读取该文件，将值填入“本地演示操作员”页面。密钥不会进入前端构建、API 返回或源码；页面只在内存中保留输入。也可按 [服务端说明](../../server/README.md) 自行设置环境变量并分别启动。

前端单独启动：

```sh
cd frontend
npm run dev
```

后端单独启动，在仓库根目录：

```sh
.venv/bin/python -m uvicorn server.app.main:app --host 127.0.0.1 --port 8000
```

## 可操作的页面

- 我的进度：查看当前阶段、已有结果和下一步，支持已有租约独立进入。
- 租房偏好：编辑合成样例，保存草稿，核对摘要并确认准确版本，再生成推荐。
- 房源推荐：显示原模块的推荐、全量合格、待确认、排除及重复记录；查看依据，比较确认版本，明确选房和导出。
- 合同复核：独立同意成功后开放文件选择；上传合成 TXT/DOCX/PDF，展示复核状态、字段来源、发现、修正和问题清单。
- 租后服务：确认租约资料后生成计划，编辑任务及证据，确认改期，跟进押金和争议，准备离线草稿，显式开启本地提醒。
- 本地演示操作员：当前案例的合同人工决定及押金门禁，权限由服务器配置验证。

## 演示路径

正常路径：新建案例 → 确认偏好 → 生成推荐 → 选择 DEMO-006 → 确认选房 → 合同复核 → 同意处理 → 下载并上传正常合成合同 → 确认是合成文件 → 上传并复核。预期显示 Reviewed 对应的“复核完成”，无发现项时不编造问题。

合同冲突：在合同页下载“租金冲突合同”后上传，预期等待人工复核；租客不能生成问题或自行放行。可在操作员页面记录决定，再回到租客页面读取有效结果。

零匹配与版本：修改期望和最高周预算为 AUD 1 → 保存 → 重新确认 → 生成推荐。空推荐为有效结果，旧报告可通过版本选择查看。

租后服务：直接进入 → 核对并确认合成租约 → 创建计划 → 编辑任务 → 提议新退租日期并明确确认。押金跟进可先建立记录、确认事实并激活，再登记有争议的扣款主张；UnderReview 时需要操作员处理，跟进草稿为 prepared_not_sent。

## 状态、时间与存储

浏览器仅保存当前案例引用和界面状态。确认版本、报告、选房包、合同同意和文件、复核历史、请求收据及 M4 案件在服务端 `.runtime/` 内保存。关闭页面后重开可恢复已提交结果。未保存表单输入不跨页面持久化，切换前请保存草稿。

房源评估和选房分别回放 2026-09-17 09:00 / 10:00 +10:00，合同规则参考日期为 2026-10-15。M4 使用独立单调演示时间，查询提醒推进至合成场景 2026-11-03 09:00 +11:00 检查点。来源观察时间不改成今天。

提醒默认关闭；开启后只有活跃页面每 30 秒查询，页面关闭不保证投递。上传限 2,000,000 字节，PDF 最多 10 页，扫描件依赖可用本机 OCR。合同 Reviewed 不表示合法认证、签约批准或租约成立；M3 到 M4 经租客表单确认衔接。

接口约定见 [api-contract.md](api-contract.md)，实际验证与限制见 [verification.md](verification.md)。
