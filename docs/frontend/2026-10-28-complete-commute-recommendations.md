# 通勤推荐全量展示与换批

2026年10月28日，悉尼时间。承接 `2026-10-27-agent2-chat-ui-handoff.md`。

## 用户确认的界面

- 推荐状态统一显示“已筛选”。移除“通勤时间参考”独立分组和待核对房源区，不把未知或超限房源混入合格结果。
- 区域按钮最前面是“全部”，默认选中；各区按钮只过滤本次结果，点击“全部”恢复全部，切换时回到第一页。
- 删除日期、到达时刻及“单程目标／硬条件”的整行小字。改用独立标签，例如“公共交通 ≤30分钟”。
- 保留卡片的平均通勤；平均值仍不是公共交通30分钟硬条件的判断依据。
- 全部合格房源和区域均可查看，每页12套；12是页面大小，不再是普通推荐的返回上限。
- 新增“换一批”，保留已确认需求，优先展示之前较少出现在首屏的房源；同条件的重复推荐也轮换首屏顺序。

## 数据与行为

普通查询遍历当前库存，返回所有满足预算、房型、所选通勤方式和其他明确限制的结果。来源明确的街道／区域估算只有区间上限满足通勤最大值才进入同一合格列表；其估算来源和位置精度仍保存在数据中，不能冒称楼栋实测。

没有主动提供到校时刻时不再追问、不填入默认时间。有明确到校时刻时仍保留原条件，按计划班次核对。该路径每轮外部查询保持12套及原有时间预算，“换一批”继续核对其他房源，并合并30分钟内同一库存、同一完整条件和同一到达目标下的有效历史结果；不把尚未核对的房源当作符合条件。

保存候选和显式引用支持完整结果，不再限制在最后100条。模型摘要仍有限制：通勤推荐每条消息只发送首屏摘要，并包含用户明确选中的卡片。大结果保存时使用同一个Agent1/网站数据库事务，避免大报告写入后再次读取造成锁等待。

聊天意图与推荐解释的temperature默认0.6，可用 `RENTAL_AI_ASSISTANT_TEMPERATURE` 配置。合同及需求字段提取等任务保持0；提高temperature不改变库存事实或硬条件。
