# 推荐链路四项优化

## 用户流程

1. 通勤卡片和详情标题展示所选交通方式的时间，不再展示跨方式平均值。有单套路线时显示“公共交通约 28 分钟”；只有粗略范围时显示“公共交通估算 22–30 分钟”。收藏、推荐表格和聊天卡片使用同一辅助函数；详情保留其他方式供查看。按用户所选模式传递地图链接和结果上下文。
2. 聊天顶部常驻“本次找房条件”，预算、房型、交通方式/时长、区域均可点击修改。应用后直接更新工作会话并重算完整结果，显示修改项和前后数量；刷新会话仍保留这些条件。已确认偏好、收藏、选定房源及合同不被此操作改写，后续同步继续走现有核对流程。
3. 新推荐卡片展示数据支持的理由：与预算/周租筛选上限的实际差额、所选方式通勤、满足的卧卫和车位要求。个人或每间预算不被当成整套广告租金；缺少交通数据时不编造时长；房型不符时不声称满足要求。房源推荐表格地址下方也展示理由。
4. 零结果时分别计算预算 +50、通勤 +10、区域不限，每个选项只改变一个条件。显示实际套数，仍为零的选项不可应用。聊天和独立房源目录页均支持点选后重筛，其他约束保持；不会自行放宽条件。

## 实现

- `assistant/recommendation_options.py`：规范化筛选、计价上下文及单条件反事实计数。
- `assistant/recommendation_workspace.py`：案例归属、会话/资料/目录版本校验、请求幂等、追加新结果及历史报告快照。所有重算使用相同本地目录和交通参考，不调用外部 AI 或交通服务。
- GET `.../conversations/{id}/recommendation-context`：只读当前条件、匹配数及备选。
- POST `.../conversations/{id}/recommendation-adjustments`：用户明确应用后修改工作条件。
- POST `.../assistant/recommendation-preview`：独立目录页只读计算备选，不保存会话或案例。
- `cached_plan.py`、`assistant/tools.py`：新结果携带对应条件和筛选元数据，全部匹配房源仍完整提供、分页显示。
- `RecommendationControls.tsx`：可点击条件、修改表单、零结果选项和失败保留。失败时可关闭表单、读取或重试，不锁死聊天。
- `recommendationFacts.ts` / `ListingReasons.tsx`：纯数据理由。
- `commuteSummary.ts::selectedCommute`：统一选定模式、来源时效及估算范围。旧 `average` 字段仅兼容已有辅助函数调用，界面不再使用它。
- 移除历史推荐报告读取中的 30 分钟会话过期规则；保留需求、案例、目录和区域资料变化检查，交通参考仍在实际匹配时按来源时效核对。

- 81 条后端测试通过：工作条件修改、单条件实际计数、只读查询、请求回放、冲突/归属、无到校时刻依赖、全量目录发现、公交及路网参考和粗略估算。
