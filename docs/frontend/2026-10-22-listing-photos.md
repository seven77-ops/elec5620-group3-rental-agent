# 房源原广告照片接入

推荐列表地址左侧增加缩略图，点击可打开原有详情抽屉。详情展示相册，可放大和切换图片，并显示原广告来源、图片观察日期。缺图或图片加载失败显示“暂无照片”。维持白蓝主题、原有筛选、列顺序和候选保存流程；未接入地图、付费 API 或新密钥。

## 数据

- 原有 500 条房源、71 个区域未修改。
- 已覆盖 335 套房源，共 1002 张图片；165 套暂缺可用图片来源。
- 图片网址来自对应 Domain 原广告页面中明确标记的 Property Gallery，最多取前三张。未选取经纪人头像、品牌标志、户型图或其他推荐房源图片。原广告可能复用较早上传的图片，图片路径中的数字不作为当前广告 ID。
- `agent2/data/real/photos.json` 单独保存广告 ID、精确来源 URL、观察时间和 CDN 图片地址；运行时不抓取外部网页，也不代理图片。图片直接从原 CDN 加载，保留原图片水印。
- 来源为公开广告快照；广告图片不表示当前仍在租，也不修改租金、卧卫车位、房源核实状态或未知字段。
- 未保存照片二进制文件。外部链接以后可能失效，前端会回退缺图状态。

## 接口与兼容

`GET /api/v1/listings` 及详情响应增加 `photos: [{url, source_url, captured_at}]`。目录元数据增加 `photo_listing_count` 和 `photo_count`。没有侧文件时返回空照片数组；前端也兼容旧响应缺少 photos。

侧文件校验已知房源 ID、精确原广告来源、带时区的 ISO 时间、图片数量和 HTTPS 域名白名单。原数据指纹仍为 `03302a834d238d453d6bcc880ec2d7c31d704a8cb0cb3421013252a67f6429dc`；图片与用于候选验证的基础房源数据分开，已有保存报告不失效。

## 验证

1. 先编写侧文件及图片行为测试，确认缺少 photos/参数与校验功能时失败，再实现功能。
2. 后端完整测试：203 项通过；新增侧文件测试和 Agent2/候选后续相关回归：22 项通过。
3. 前端构建、9 项 API 测试通过；构建仍有既有 vendor 包体积提示。
4. 照片、Agent2 和候选后续页面测试合计 13 项通过：缩略图键盘打开、相册预览、来源、缺失/损坏回退、翻页、更换房源无旧图、360px 宽度及原选房流程。
5. 对 1002 个真实图片 URL 逐一 HEAD 检查，全部 HTTP 200 且 Content-Type 为图片。实际 Chrome 加载 Annandale 房源缩略图和放大预览，解码尺寸 1620×1080，无页面异常；桌面和手机截图检查通过。
6. 原用户案例关联的 44 条持久化记录逐条比对未改变；基础目录指纹一致。
7. 独立代码复核无需修复的发现。

本轮未修改聊天、合同、租后服务逻辑，也没有将外部照片发给模型。
