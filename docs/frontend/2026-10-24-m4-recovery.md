# M4 页面补录恢复验证

日期：2026-10-24（Sydney）。对应 M4_integration_review.md 中的 P1、P2。仅修改网页接入，继续使用原 M4 的状态和资料校验。

## 页面变化

- 已建案资料条增加“补充租约资料”，显示尚缺的房间、地毯、室外、家具或清单核对项。编辑窗口预填当前资料，未知项保持未知；用户明确勾选确认后调用 revise_tenancy，来源版本递增，保留同一案件、租约 ID 及证据。计划已确认或押金已激活时按钮禁用。
- 押金 Draft 增加“补录押金资料”，可补编号或绑定已登记的 deposit_record。保存调用 open_bond 更新同一草稿，不自动激活或新增事实。激活后补录入口关闭。
- 两种编辑窗口保留输入，错误时提供原请求重试和读取最新状态；重试复用原请求身份。刷新后的租约来源版本变化会要求重新勾选确认。

## 实测

使用隔离运行目录 `/tmp/rental-m4-recovery-tests`，真实房源模式、虚构租约和押金信息；没有调用真实模型、交通或官方押金系统，没有发送邮件。

新增 `frontend/e2e/m4-recovery.spec.ts` 六项浏览器测试通过：

1. 仅填地址、未知物业属性建案；确认计划被原 M4 阻止；原案补齐一间房与三项属性，来源 v1→v2；确认计划变为 Active。已有证据及租约、案件 ID 保留。
2. 空编号建 Draft；直接激活被阻止且不记入事实；补录编号后激活成功。重复原激活请求不重复历史。
3. 已登记押金凭证可绑定同一空编号草稿并激活；其他证据类型不进入选择项。
4. 租约补录已提交但响应丢失：表单保留输入，原请求重试成功，来源及案件版本只增加一次。
5. 押金补录响应丢失：原请求重试不重复增加版本或事实。
6. 租约修改遇到案件版本冲突：读取最新状态后保留地址输入，可重新保存；并发新增的证据保留。

原有 `living-services.spec.ts` 六项浏览器回归通过；Agent4 原模块 57 项、server.tests.test_api 25 项通过。TypeScript 与 Vite 生产构建通过，仍有既有 vendor 大包提示。
