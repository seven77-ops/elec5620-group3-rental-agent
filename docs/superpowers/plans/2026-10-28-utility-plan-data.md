# Utility plan data implementation plan

**Goal:** Store official Sydney/NSW internet, electricity, gas and water plan observations in SQLite and use them in grounded chat answers and existing provider cards.

**Architecture:** Versioned public JSON seed plus a dedicated `utility_catalog.sqlite3` inside each configured runtime; tables retain snapshot metadata and plan JSON, indexed by provider/category. A shared read-only query service filters valid observations and prepares price text. Existing per-case supplier choices and confirmation flows remain separate.

**Constraints:** AUD amounts retain billing units and GST provenance. Broadband introductory price, duration, expiry, ongoing price, speed and hardware conditions remain distinct. AER tariffs retain all blocks/time windows, network, postcode and eligibility; never flatten TOU/demand into a single rate or claim address availability. Sydney Water fixed owner charges are separate from conditional tenant usage. Expired/stale observations are labelled and excluded from recommendations. No personal address sent to suppliers; no bookings, purchases or supplier changes.

1. Research AER documented public plan APIs, five internet suppliers' official pages/CIS, Sydney Water and NSW tenancy guidance. Save structured observed facts and source metadata to `server/app/living/data/utility-plans.json`; add a reproducible explicit AER refresh script.
2. Add failing tests in `server/tests/test_utility_plans.py` for durable SQLite seeding, source/units, expiry and promo expiry, ongoing-budget filtering, tariff boundaries, missing availability and grounded chat answers. Run `python -m unittest server.tests.test_utility_plans` before implementing.
3. Implement `UtilityPlanCatalog(database, seed_path=None)` with `search(category=None, provider_id=None, postcode=None, on=None)`, immutable snapshots and fingerprint-based import. Wire it once through `Services`. Enrich `LivingService.directory()` with per-provider plan observations; keep fixture-directory injection isolated.
4. Implement a focused `utility_advice.py` for category/provider and explicit budget/speed queries, deterministic candidate ranking and source-linked pricing explanations. Chat returns existing provider cards populated with matching plans; monthly budgets compare ongoing charges and first-year totals exclude unknown extras. Water is explained as an address-assigned service.
5. Reuse `UtilityPlans.tsx` in both `Utilities.tsx` and `LivingCards.tsx`. Show compact plan rows with promotional/ongoing fees, rates/units, conditions, sources and observation date, expandable for the full provider list. Test real API/chat/page/mobile in an isolated runtime, run affected backend tests and TypeScript/Vite build, then restart only the actual preview API to import the catalogue. Preserve user cases and the 1,000-house catalogue.
