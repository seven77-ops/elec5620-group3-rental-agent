# 推荐链路四项优化

**目标：** 通勤展示与筛选统一、结果条件可快捷调整、房源推荐理由可追溯、零结果提供真实计算的单条件替代方案。

**架构：** 复用当前目录及既有班次/路网参考。增加确定性的会话筛选修改接口，不经过 AI 解释按钮操作；保留版本冲突、请求回放及案例归属校验。修改本次工作条件并追加结果，不自动改写已确认偏好或选定房源。零结果逐项计算预算 +50、通勤 +10、区域不限，其他条件不变。所有结果继续完整提供并分页。

**边界：** 不引入到校时刻；不使用跨交通方式平均；范围按区间展示并按上限筛选；不捏造金额节省、交通耗时或无结果新增数量；只有点击应用才调整条件。合同、租后及已保存案例数据保留。

- [x] 通勤展示辅助函数及历史报告过期回归：先补选定方式/区间/缺失/超过30分钟的用例，再改卡片、详情、收藏、房源推荐页与历史报告读取。
- [x] 后端确定性增强：生成逐套理由、单条件备选计数、变化摘要；以目录实际匹配结果验证数量，覆盖案例归属、过期输入和幂等。
- [x] 新增会话条件调整接口，接入已有快照、消息和报告保存机制；不调用外部 AI/交通，不写已确认偏好。
- [x] 前端可点击条件条、简洁修改弹窗、理由列表和零结果调整按钮，展示条件变化与前后数量。
- [x] 临时环境跑完整页面链路及相关回归、构建和格式检查；核对原有数据摘要后重载本地 API。
- [x] 记录完成内容及验证结果。
