# Real data workbench implementation plan

> **For agentic workers:** Execute inline in this chat. Use test-driven-development for business behavior and requesting-code-review for the final independent review.

**Goal:** Make the researched government rental data usable in the app and supply honest, credential-gated real listing and commute collection.

**Architecture:** A separate `server/app/real_data/` feature owns offline rent benchmarks, bounded providers, input validation and HTTP routes. Existing repository storage saves manually entered real listings; a lazy React page consumes stable DTOs. The synthetic evaluation and contract path is unchanged.

**Tech Stack:** Python 3.13, FastAPI, httpx, existing SQLite repository, React/TypeScript/Ant Design, Playwright. Use existing dependencies; extraction uses the bundled Python/openpyxl runtime only.

## Global constraints

- Source periods are September 2026 and April–June 2026, not the request date.
- Initial market coverage: postcodes 2008/2037/2042/2050, flat/unit, 1/2 bedrooms, whole-property base weekly rent in AUD.
- No provider calls on startup, automatic retries, secret disclosure, arbitrary URL fetches, synthetic relabelling or AI calls.
- No remote publishing or paid account creation. Existing local changes remain intact.

## Task 1: offline government benchmark

Files: `agent2/data/market/nsw-usyd-2026.json`, `tools/build_market_snapshot.py`, `server/app/real_data/market.py`, `server/tests/test_real_market.py`.
